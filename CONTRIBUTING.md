# Как внести вклад в Philoloom

Спасибо за интерес к проекту! Исправления и новые идеи можно предложить через GitHub Issues или Pull Requests. Пожалуйста, придерживайтесь предметной точности и уважительного тона.

## Какие изменения полезны

- Исправления фактических ошибок, дат, атрибуции цитат и библиографии.
- Уточнение философских позиций и объяснений, в том числе альтернативных интерпретаций.
- Новые темы и проверяемые связи между существующими сущностями.
- Улучшения доступности, поиска, производительности и интерфейса.

Для крупных изменений сначала откройте Issue, чтобы согласовать структуру и избежать дублирования.

## Как устроен контент

Статьи хранятся в `content/knowledge/Философия/` в виде Markdown, а их метаданные и связи — также в CSV-файлах `*_all.csv`. У каждой сущности есть стабильный 32-символьный ID, используемый во внутренних ссылках. Публичные URL для тем, истории и личностей определяются в `content/slugs.json`.

При изменениях:
1. Сохраняйте идентификаторы существующих сущностей и их публичные URL.
2. Обновляйте соответствующие Markdown и CSV вместе, в том числе обратные отношения, если это явно предусмотрено полями.
3. Для новой публичной записи добавьте уникальный slug и нужные записи в связанные реестры.
4. Приводите проверяемые источники, отделяйте цитату от интерпретации и не создавайте смысловые связи только по совпадению слов.
5. Не добавляйте личные заметки, приватные материалы, непроверенные изображения или чужой контент без разрешения.

**Формат данных пока не поддерживает YAML front matter.** Первая строка статьи должна оставаться Markdown-заголовком `# Название`. Подробности и правила короткого вступления — в [редакционном руководстве](docs/CONTENT_GUIDE.md).

## Проверка изменений

После установки зависимостей и Git LFS:

```bash
python3 scripts/audit_content.py --summary --strict
make check
```

Если менялся интерфейс, проверьте его в браузере на узком и широком экранах. GitHub Actions дополнительно запускает сборку, тесты и браузерную проверку при создании PR.

## Как отправить Pull Request

Создайте fork, откройте отдельную ветку, внесите тематически связанные изменения и отправьте PR в `main`. В описании объясните цель, укажите изменённые сущности, приложите источники и результат проверок. Избегайте несвязанных массовых переформатирований.

Слияние в основные ветки выполняется сопровождающим через **Squash and Merge** после проверки. Сам факт отправки PR не гарантирует включения предложенного материала.

## Авторские права

Добавляйте собственные тексты и материалы, которыми вправе делиться. Цитаты оформляйте с указанием автора и произведения, изображения — с доказуемым происхождением и допустимыми условиями использования. Лицензия репозитория пока не объявлена: это важно учитывать перед повторным использованием файлов.
