# PhiloLoom

Личный философский справочник с оформлением в стиле Notion. Сайт собирается из Markdown и CSV в набор статических HTML-страниц. Доступ к Notion для сборки и просмотра не требуется.

## Требования

- Python 3.9 или новее с модулями `venv` и `pip`.
- Git LFS для загрузки изображений из репозитория.
- `make` для коротких команд запуска; ниже приведены команды без него.

## Первый локальный запуск

Открой терминал в папке репозитория. Для текущего расположения на macOS:

```bash
cd /Users/mksddn/WORK/GIT/philoloom
git lfs install --local
git lfs pull
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
make serve
```

Открой http://localhost:8000 в браузере. Терминал должен оставаться открытым. Для остановки сервера нажми **Ctrl+C**.

Установка зависимостей требует доступа к интернету. После установки сайт работает локально, но внешние ссылки по-прежнему ведут на другие сайты.

## Повторный запуск

В папке репозитория выполни:

```bash
source .venv/bin/activate
make serve
```

Команда `make serve` пересобирает сайт и запускает сервер на порту 8000. После изменения исходников останови сервер и выполни её снова, затем обнови страницу в браузере.

## Запуск без make

После установки зависимостей и активации `.venv`:

```bash
python3 scripts/build.py
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Если порт 8000 занят, замени его, например, на 8001 и открой http://localhost:8001.

## Только сборка

После активации `.venv`:

```bash
make build
```

Или без `make`:

```bash
python3 scripts/build.py
```

Результат находится в `dist/`. Эту папку можно разместить на статическом хостинге. Для локального просмотра используй HTTP-сервер: открытие HTML напрямую как файла не обеспечивает работу поиска.

## Где хранится содержимое

- `content/notion/` — исходный экспорт: Markdown-страницы, CSV с записями и связями, вложенные изображения.
- `site/style.css` — оформление сайта.
- `site/app.js` — поиск, вкладки, боковая панель и настройки чтения.
- `scripts/optimize_images.py` — подготовка адаптивных WebP.
- `content/image-manifest.json` — размеры, контрольные суммы и варианты изображений.
- `content/optimized/` — готовые WebP для сборки.
- `scripts/build.py` — сборка страниц и поискового индекса.
- `requirements.txt` — зависимости сборки.
- `dist/` — сгенерированный сайт; исключён из Git.
- `.venv/` — локальное окружение Python; исключено из Git.

Редактируй исходники, а не файлы в `dist/`: сборка полностью заменяет эту папку. При изменении названий и связей согласованно обновляй соответствующие Markdown и CSV; идентификаторы в именах файлов используются для внутренних ссылок.

## Работа в облачной среде

После клонирования репозитория перейди в его папку и выполни те же команды установки и сборки. Путь `/Users/mksddn/WORK/GIT/philoloom` относится только к текущему компьютеру; в облаке используй путь к своему клону. Все исходные данные и настройки сборки находятся в репозитории. Node.js, локальные файлы вне репозитория и подключение к Notion не нужны.

## Ограничения экспорта

В архиве отсутствуют восемь PDF-заданий, на которые ссылаются записи. Они отмечены на сайте как отсутствующие в экспорте. Внешние материалы, доступные только по ссылкам, не скачиваются при сборке.


## Карточки, боковая панель и миниатюры

Нажатие на запись, внутреннюю ссылку или результат поиска открывает подробности в боковой панели. В ней доступны возврат, следующая запись и открытие на всю страницу. Закрыть панель можно крестиком, клавишей **Esc** или нажатием снаружи. Кнопки «Назад» и «Вперёд» браузера также работают. На узком экране панель занимает всю ширину.

Для каждого раздела доступны представления «Галерея», «Список» и «Таблица». Выбранный вид сохраняется в браузере отдельно для каждого раздела. По умолчанию темы и статьи показаны галереей, цитаты — списком, история философии и личности — таблицами. Нажатие на заголовок столбца сортирует таблицу. Изображения в тексте можно увеличить нажатием. Поиск открывается кнопкой или сочетанием **Ctrl+K / ⌘K**. При системной настройке уменьшения движения анимации отключаются.

Данные закладок хранятся в `content/link-previews.json`, скачанные миниатюры — в `content/previews/`. Обычная сборка использует этот кэш без сетевых запросов. Если изображение не удалось скачать, сайт пробует загрузить его по исходному адресу; при ошибке миниатюра скрывается. Некоторые исходные портреты также остаются внешними изображениями.

Чтобы обновить данные превью и скачать доступные изображения, активируй `.venv` и выполни:

```bash
python3 scripts/refresh_previews.py --download-images
make build
```

Обновление требует интернета и запрашивает только публичные ссылки, присутствующие в экспорте. Недоступные сайты не останавливают обновление: ранее сохранённые данные сохраняются. Сами статьи и страницы по ссылкам не копируются. Сайты без доступной миниатюры отображаются текстовыми закладками.


## Вкладки, тема и исходные данные

Разделы переключаются вкладками; адрес с фрагментом `#…` открывает нужный раздел напрямую. Вкладками можно управлять стрелками, Home и End. Все разделы и ссылки на записи присутствуют в исходном HTML. Без JavaScript разделы отображаются последовательно; каждая запись также имеет самостоятельную HTML-страницу. Содержимое не требуется загружать через боковую панель для чтения или обхода ссылок.

Светлая и тёмная тема автоматически следуют настройке системы или браузера через `prefers-color-scheme`. Смена темы не требует перезагрузки.

Пустые свойства не выводятся в подробностях; полностью пустые столбцы исключаются из таблиц. Поля «Конспект» исключены из интерфейса и поискового индекса. Исходные Markdown и CSV сохранены без изменений: исключение из интерфейса не удаляет ссылки из оригинального экспорта в репозитории.

Обложка главной страницы хранится в `site/assets/forest-cover.jpg` и копируется в сборку. Источник: https://images.unsplash.com/photo-1473448912268-2022ce9509d8. Для отображения обложки сетевое подключение не требуется.


## Оптимизация изображений и Git LFS

Оригиналы сохраняются в исходных папках. Сайт использует WebP из `content/optimized/`: для обложки готовятся размеры 640, 1280 и 1920 пикселей, для обычных превью — до 320, 640 и 960 пикселей. Увеличения маленьких оригиналов нет. Для диаграмм создаётся также вариант в полном исходном разрешении; кодирование диаграмм выполняется без потерь. Браузер выбирает подходящий размер через `srcset`, а при увеличении открывается самый крупный вариант.

`make build` и `make serve` автоматически подготавливают изображения. Неизменившиеся файлы используются повторно. Для запуска только оптимизации:

```bash
make images
```

После обновления зависимостей проекта выполни `python3 -m pip install -r requirements.txt` в активном `.venv`. Для обработки изображений используется Pillow; дополнительные системные программы не нужны.

Бинарные изображения, включая оригиналы и WebP, отслеживаются правилами `.gitattributes` через Git LFS. Эти правила применяются при добавлении файлов в Git; изменения правил и сами файлы должны попасть в один коммит. LFS-объекты передаются на сервер при обычном `git push` с установленным Git LFS. Старые коммиты при этом не переписываются.

В новом локальном или облачном клоне, до сборки:

```bash
git lfs install --local
git lfs pull
```

Сборка проверяет наличие реальных изображений и останавливается с подсказкой, если вместо них остались LFS-указатели. Тяжёлые оригиналы в `dist/` не копируются: туда попадают только подготовленные варианты. Часть недоступных внешних изображений может по-прежнему загружаться по исходным адресам.

## Чтение и связанные записи

Кнопка «Режим чтения» доступна на страницах и в боковой панели. В этом режиме скрываются свойства записи, а размер текста регулируется от 16 до 24 пикселей. Можно выбрать узкую, обычную или широкую строку. Настройки сохраняются в этом браузере.

Под текстом расположен блок «Связанные записи». Он использует явные связи из справочника и учитывает обратные ссылки. Неподтверждённые смысловые связи автоматически не добавляются. Все ссылки присутствуют в статическом HTML и доступны без JavaScript. Путь в боковой панели показывает раздел и текущую запись; раздел в пути открывается обычной ссылкой.

## Проверки

В активном `.venv`:

```bash
make check
```

Команда собирает сайт и проверяет внутренние ссылки, доступность разделов в HTML, обратные связи, размеры изображений, сохранение текста на диаграмме без потерь и повторное использование готовых WebP.
