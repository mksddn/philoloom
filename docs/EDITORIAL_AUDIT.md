# Редакционная инвентаризация Philoloom

Воспроизводимая инвентаризация выполняется существующим инструментом `scripts/audit_content.py`:

```bash
python3 scripts/audit_content.py --summary --report editorial-report.json
```

Файл `editorial-report.json` содержит полный перечень экспортированных Markdown-записей с исходными идентификаторами, закреплёнными публичными URL, размерами содержательного текста, первыми абзацами, входящими и исходящими ссылками, замечаниями и приоритетом проверки. Результат также прикладывается к проверке Pull Request в GitHub Actions (артефакт `editorial-audit`). Это **генерируемый отчёт**, его не нужно вручную редактировать и коммитить.

## Область охвата

- Публичные типы: «Темы», «История философии», «Личности», «Цитаты».
- Исходные самостоятельные работы и корневая страница включены в технический реестр, но получают статус `excluded` и **не входят** в публичную редакционную очередь.
- Цитаты имеют отдельный флаг `quotation_source_review`: их текст находится в заголовке Markdown, поэтому отсутствие текста под заголовком само по себе не означает пустую цитату.
- Идентификаторы источников стабильны. Публичные адреса читаются из `content/slugs.json`; цитаты привязаны к якорям главной страницы.
- Отношения из `*_all.csv` сопоставляются с Markdown в порядке экспорта, как в действующем сборщике. Обратные связи считаются отдельно, без превращения их в новые философские утверждения.

## Статусы и очередь

| Статус | Значение |
| --- | --- |
| `empty` | Пустая / шаблонная опубликованная запись. Приоритет 1. |
| `stub` | Недостаток собственного текста или самостоятельного начального объяснения. Приоритет 2. |
| `needs-review` | Имеется материал, но философская и редакционная достоверность ещё не подтверждены. Приоритет 1 при структурной ошибке, иначе 3. |
| `ready` | Только после содержательной проверки редактором; автоматическая эвристика **не присваивает** этот статус. |
| `excluded` | Вне публичной редакционной очереди. |

В отчёте дополнительно учитываются дубли заголовков, отсутствующие цели связей, необнаруженные slugs, отсутствие краткого вступления, недостающие исходящие/входящие связи и необходимость проверки источников. Длина — лишь сигнал для ручной проверки, а не механический критерий полноты.

Порядок исправления: сначала шаблоны, пустые записи, ошибки связей и дубли (без автоматического удаления), затем неполные статьи и биографии, после — исправление терминологии и библиографии, наконец — расширение и типизация обоснованных связей. Ни одна подсказка аудита сама по себе не доказывает исторический или философский факт.

Параметр `--strict` проверяет структурные проблемы и может завершаться с кодом 1; в CI он пока намеренно не используется, чтобы не блокировать сборку существующими недостатками. Проверка кода отдельно запускается командой `python3 -m unittest discover -s tests -v`.

Учебные PDF хранятся только в контексте ChatGPT, вне публичного репозитория. Они используются как материал для сопоставления, но не публикуются и не копируются в статьи механически.
