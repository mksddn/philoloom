# Готовность к публикации Philoloom

Состояние на 17 ноября 2026 года. Публичный сайт и история репозитория — разные поверхности: исключение материала из HTML **не делает** исходники приватными.

## Реализовано и проверено

- **PR #13:** 113 статей и 11 встроенных цитат; вступления раскрывают философскую мысль, комментарии под цитатами убраны. Формальный аудит и регрессионные тесты пройдены.
- **PR #14:** 2D-карта с 113 публичными узлами, навигацией по соседям, поиском, клавиатурой и доступным списком без JS. Публикуются только связи из явных исходных полей/ссылок и дополнительно три интерпретированные направленные связи с локаторами Stanford Encyclopedia of Philosophy.
- **Редакторская работа:** новые карточки создаются в `content/editorial/` со статусом `draft`; исходный экспорт Notion не изменяется. Публикация требует содержательного вступления, основного текста, библиографии (темы и периоды) и связи с опубликованной записью. Проверяются дубликаты среди редакционных и исходных заголовков.
- **SEO:** `PHILOLOOM_SITE_URL` и `PHILOLOOM_CNAME` в GitHub Actions; канонические адреса, sitemap, robots и CNAME рассчитываются совместно. Без новых переменных по-прежнему используется GitHub Pages URL.

Проверки PR #14: `python scripts/audit_content.py --strict`, `make check`, браузерный smoke-test (мобильные, планшетные, десктопные размеры и обе темы). Точный SHA и актуальный статус CI проверять на странице PR перед слиянием.

## Блокирующий вопрос: граница публичного и личного

Репозиторий **публичный**, а исходный архив в `content/notion/` содержит отдельную категорию учебных работ. Сборка сайта исключает её из публичных страниц, поиска и графа, но файлы по-прежнему доступны через сам GitHub и исторические коммиты. Ни `.gitignore`, ни `robots.txt`, ни удаление файлов в новом коммите **не удалят** их из прежней истории.

Для реального разделения требуется:

1. Предварительно сохранить исходные личные записи в **отдельном приватном месте** и убедиться в полноте переноса.
2. Убрать их из текущего публичного дерева, исправить экспорт/документацию/тесты, чтобы последующие обновления не возвращали их.
3. Отдельно согласовать **переписывание истории** публичного Git-репозитория и ограничения этого действия (форки, клоны, кэши, ранее скачанные копии). Это потенциально разрушительная операция, её нельзя выполнять без осознанного решения владельца.
4. Снова проверить доступность репозитория и сайта, а также workflow GitHub Pages.

**Статус:** не устранено. Отсутствие материалов на сайте недостаточно для выполнения исходного требования о приватных заметках. Не объявлять проект полностью готовым к безопасной публикации источников.

## Внешние действия

- Приобрести/подтвердить собственный домен, настроить GitHub Pages, DNS, HTTPS и переменные Actions (не подставлять вымышленный домен).
- Повторно проверить canonical, sitemap и редиректы на работающем адресе и зарегистрировать сайт в поисковых инструментах.
- Для академического статуса `ready`: последовательно сверить конкретные тезисы и русские переводы по первоисточникам. Наличие 18 учебных PDF, библиографии или трёх проверенных отношений не заменяет проверку всех 124 записей.
- Провести правовую проверку лицензий изображений и источников, а также полный внешний URL-аудит.

## Последовательность безопасного выпуска

1. Разрешить вопрос публичных исходных файлов и внешних ограничений.
2. Утвердить изменения **PR #13**; выполнить **Squash and Merge** в `main`, удалить ветку.
3. Перебазировать PR #14 на новый `main`, чтобы остался только его собственный diff; заново дождаться CI.
4. Принять PR #14 через **Squash and Merge**, удалить ветку, проверить Pages и реальный мобильный сайт.
5. DNS и индексация — отдельный завершающий этап после владения доменом. Академическая сверка остаётся редакционным процессом, а не машинным «готово».
